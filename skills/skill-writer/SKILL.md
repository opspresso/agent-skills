# 스킬 작성 스킬

Agent Studio의 스킬(SKILL.md)을 설계·작성·개선할 때 따르는 지침이에요.
완성된 SKILL.md 초안을 산출물로 제공하고, 어떤 선택을 왜 했는지 짧게 설명해요.

## 스킬이 로드되는 방식 (전제)

- 시스템 프롬프트에는 스킬의 **이름 + description만** 표에 노출돼요.
- 본문 전체는 모델이 필요하다고 판단해 `Skill` 툴을 호출할 때만 로드돼요
  (progressive disclosure).
- 따라서 **description이 곧 라우팅 신호**예요. description이 "무엇인지"만 말하고
  "언제 쓰는지"를 말하지 않으면, 모델은 그 스킬을 영영 로드하지 않아요.

## description 작성 규칙

1. **트리거를 명시해요** — "사용자가 ~를 요청하면", "~ 작업을 시작하기 전에"
   처럼 로드 시점이 문장 안에 드러나야 해요.
2. **산출물이나 절차를 한 구절로 요약해요** — 모델이 로드 전에 기대 결과를
   알 수 있게 해요 (예: "GenerateImage 툴을 호출해 실제 이미지를 생성해요").
3. **사용 언어를 통일해요** — 한 플랫폼의 스킬 description은 같은 언어로 써요.
   에이전트 프롬프트가 한국어라면 description도 한국어가 매칭이 잘 돼요.
4. 두세 문장 이내로 유지해요. 상세 규칙은 본문으로 보내요.

좋은 예:
> 사용자의 아이디어를 좋은 영어 이미지 프롬프트로 다듬은 뒤 GenerateImage 툴을
> 호출해 실제 이미지를 생성해요.

나쁜 예:
> Natural, helpful conversation style for Korean users
> (— 무엇인지는 알지만 언제 로드해야 하는지 알 수 없어요)

## 본문 구성 순서

1. **한 줄 정의** — 이 스킬이 적용되는 상황을 첫 문단에서 다시 확인해요.
2. **반드시 지킬 것** — 하드 룰 한두 개만. "절대/반드시"를 남발하지 않아요.
3. **절차 또는 규칙** — 번호 목록이나 표로. 한 문장에 한 지시만 담아요.
4. **산출물 형식** — 형식이 중요하면 예시 출력을 그대로 보여줘요.
5. **예외 처리** — 모호한 요청, 도구 실패, 범위 밖 요청의 대응.

측정 가능하게 써요 — "친절하게"보다 "~요체 사용, 인사에는 한 문장으로 화답"이
재현돼요.

## 스킬 유형별 주의

- **작업 스킬** (예: image-generation, structured-output) — progressive
  loading에 적합해요. 트리거가 명확한 description이 핵심이에요.
- **스타일 스킬** (예: conversation, slack-formatting) — 항상 적용되어야
  한다면 스킬보다 에이전트 시스템 프롬프트에 직접 넣는 것을 검토해요.
  스킬로 유지한다면 description에 "답변을 작성하기 전에 로드"처럼 로드
  시점을 강제하는 문구를 넣어요.
- **도구 연계 스킬** — 본문에 어떤 툴(GenerateImage, MCP 툴 이름)을 어떤
  파라미터로 호출하는지 명시해요. 모델이 도구 존재만으로 용도를 추론하게
  두지 않아요.

## 에이전트와의 연결 규칙

스킬을 붙이는 에이전트(프로젝트 버전) 쪽에도 할 일이 있어요:

- 시스템 프롬프트에 **상황 → 스킬 라우팅 맵**을 한 단락 넣어요.
  예: "이미지 요청이면 image-generation 스킬을 먼저 로드하고, JSON·표 추출
  요청이면 structured-output 스킬을 따라요."
- 서브에이전트로 노출되는 프로젝트라면, **프로젝트 description이
  transfer_to_agent의 라우팅 신호**예요. "무엇을 잘하고 어떤 요청을 넘겨받아야
  하는지"를 description에 써요.
- 스킬 5개 이상을 한 에이전트에 붙이지 않아요 — 겹치는 트리거는 오호출을
  만들어요. 역할이 갈리면 서브에이전트로 분리해요.

## 체크리스트 (스킬 발행 전)

- [ ] description만 읽고 "언제 로드할지" 판단이 되는가
- [ ] 본문 하드 룰이 두 개 이하인가
- [ ] 도구 연계 시 툴 이름·파라미터가 본문에 있는가
- [ ] 같은 트리거를 가진 기존 스킬과 겹치지 않는가
- [ ] 이름이 소문자-하이픈 슬러그이고 디렉터리명과 일치하는가
