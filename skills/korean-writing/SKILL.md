# 한국어 사내 글쓰기

한국 회사에서 실제로 오가는 말투로 써요. 문법적으로 맞는 문장이 아니라, 받는
사람이 읽고 바로 행동할 수 있는 문장이 목표예요.

## 반드시 지킬 것

- **사용자가 주지 않은 사실을 만들지 않아요.** 금액, 날짜, 결재선, 담당자
  이름은 받은 것만 써요. 없으면 `[금액]`처럼 자리표시자로 남기고 무엇이 더
  필요한지 초안 아래 한 줄로 알려요.
- **초안을 다듬을 때 사실관계와 요청 범위를 바꾸지 않아요.** 문체만 고쳐요.
  원문이 "검토 부탁"이면 "승인 부탁"으로 올리지 않아요.

## 먼저 세 가지를 정해요

문체는 취향이 아니라 이 셋에서 나와요.

| 어디에 | 누구에게 | 기본 문체 |
|---|---|---|
| 사내 메신저 (채널·DM) | 동료, 타팀 | 해요체 |
| 사내 메신저 | 상급자, 임원 | 해요체 + 요청은 "~해 주세요"보다 "~ 부탁드려요" |
| 결재·기안 문서 | 결재선 | 합니다체 |
| 전사 공지, 대외 메일 | 불특정 다수 | 합니다체 |
| 회의록, 기술 문서 | 팀 내부 | 개조식(음슴체) 또는 해요체 — 문서 관례 우선 |

**사용자가 기존 메시지나 조직 문서를 보여줬으면 그 톤이 위 표를 이겨요.**
영어 이름을 쓰는지, 직급을 붙이는지, 이모지를 쓰는지도 거기서 가져와요.

## 존댓말

- 해요체와 합니다체를 한 글 안에서 섞지 않아요. 하나를 골라 끝까지 유지해요.
- **사물에는 존칭을 붙이지 않아요.** "금액이 100만 원이십니다" → "금액은
  100만 원입니다". "회의가 있으십니다" → "회의가 있으세요"(주체는 사람).
- **이중 경어를 피해요.** "말씀이 계셨습니다" → "말씀하셨습니다".
- **압존법은 쓰지 않아요.** 임원 앞에서도 팀장은 팀장님이에요.
- 윗사람에게 "수고하세요"는 쓰지 않아요. "고생 많으셨습니다", "감사합니다"로.
- 사과는 한 번만 해요. "죄송합니다" 다음에는 원인과 대응이 와야지, 사과를
  두 번 반복하면 내용이 사라져요.

### 걷어낼 과공손

- "바쁘신데 죄송하지만", "다름이 아니라", "혹시 실례가 안 된다면" → 용건부터.
- "확인 부탁드리면 감사하겠습니다" → "확인 부탁드려요". 감사 표현은 글 하나에
  한 번이면 충분해요.
- "~인 것 같습니다"를 사실에 붙이지 않아요. 확인한 건 확인했다고 써요.
  추측일 때만 추측이라고 밝혀요.

## 사내 메신저

- **결론을 첫 줄에 써요.** 배경은 그다음이에요.
- 한 메시지에 한 용건. 3~5줄 안에 끝내고, 넘치면 스레드로 이어요.
- **엔터로 나눠 보내지 않아요.** 한 번에 한 메시지로 보내요.
- 질문은 답하기 쉽게 만들어요 — 예/아니오나 선택지로. 열린 질문은 답이 늦어요.
- **언제까지 필요한지 반드시 적어요.** 기한 없는 요청은 우선순위가 없어요.
- 답이 없을 때 어떻게 할지 미리 적으면 회신이 빨라져요 — "금요일까지 의견
  없으면 A안으로 진행할게요".
- 멘션은 지금 행동해야 할 사람에게만. `@here`·`@channel`은 지연이 실제
  피해로 이어질 때만 써요.
- 이모지는 의미를 보탤 때만 한두 개. 모든 줄에 붙이지 않아요.

**고치기 전**

> 안녕하세요! 바쁘신데 죄송합니다 ㅠㅠ 다름이 아니라 저번에 말씀드렸던 로그
> 수집 관련 건에 대해서 혹시 확인이 가능하실지 여쭤보고자 연락드렸습니다.
> 확인 부탁드리면 감사하겠습니다!

**고친 뒤**

> 로그 수집 설정 변경 PR 리뷰 부탁드려요. (링크)
> 스테이징에서 하루 돌렸고 유실은 없었어요.
> 목요일 배포에 넣으려면 수요일 오전까지 리뷰가 필요해요.

## 결재·승인 요청

### 상신 알림 (메신저)

네 가지를 한 문단에 담아요 — **무엇을 올렸는지, 왜 필요한지, 얼마·언제까지,
언제 승인이 필요한지**.

> 데이터독 연간 계약 갱신 건 결재 올렸어요. (링크)
> 금액은 작년과 같은 1,200만 원이고, 8월 20일에 만료돼서 그 전에 갱신돼야
> 알림이 끊기지 않아요.
> 8월 14일까지 승인 부탁드려요.

### 기안문 본문 (합니다체)

```markdown
제목: [무엇에 대한 무슨 결재인지 — 한 줄]

## 요청 사항
[승인받으려는 것 한 문장. 금액·기간·범위를 숫자로.]

## 배경
[왜 지금 필요한지. 안 하면 무엇이 문제인지.]

## 세부 내역
- 금액: [산출 근거까지]
- 기간: [시작 ~ 종료]
- 범위: [포함되는 것과 빠지는 것]

## 검토한 대안
[다른 선택지와 이것을 고른 이유. 없으면 생략합니다.]

## 리스크
[예상되는 문제와 대응 방안]

## 처리 기한
[언제까지 승인되어야 하고, 늦으면 무엇이 어긋나는지]
```

- 결재선과 참조자는 조직마다 달라요. 사용자가 알려준 경우에만 적어요.
- 금액에는 근거를 붙여요. 숫자만 있으면 결재자가 되물어요.
- "필요하다고 판단됩니다" 같은 피동 표현 대신 "필요합니다"로 단정해요.
  기안문은 요청하는 문서예요.

### 리마인드와 반려 대응

- 재촉이 아니라 **기한 근거**로 다시 알려요. "혹시 놓치셨을까 봐"는 빼요.
  > 어제 올린 계약 갱신 건 다시 안내드려요. 14일까지 승인되지 않으면 20일에
  > 알림이 끊겨요. 오늘 중 확인 가능하실까요?
- 반려되면 변명하지 않아요. **무엇을 어떻게 고쳐서 다시 올릴지**만 써요.
- 조건부로 진행해야 하면 조건을 명시해요 — "선승인 후 계약서는 다음 주에
  첨부하는 방식으로 진행해도 될까요?"

## 문장 다듬기

| 흔한 표현 | 대신 |
|---|---|
| ~하도록 하겠습니다 | ~하겠습니다 |
| ~에 대해 확인 부탁드립니다 | ~을 확인해 주세요 |
| ~를 통해 진행하겠습니다 | ~로 하겠습니다 |
| 확인이 필요한 부분이 있습니다 | 확인할 게 있어요 |
| 배포가 완료되어졌습니다 | 배포했습니다 |
| 이슈가 발생한 상황입니다 | 장애가 났습니다 |
| 관련하여 공유드립니다 | (빼고 바로 내용) |

- 명사를 늘어놓지 말고 동사로 풀어요. "결제 실패 건수 증가 확인" →
  "결제 실패가 늘었어요".
- "진행", "처리", "대응"은 무슨 일인지 감추는 말이에요. 배포·정산·회신처럼
  구체적인 동사로 바꿔요.
- 한 문장에 쉼표가 셋 이상이면 끊어요.
- 영어 약어와 사내 용어는 그대로 두되, 받는 사람이 모를 수 있으면 처음
  나올 때 한 번 풀어요.

## 산출물 형식

- **완성된 본문만 코드 블록 없이 그대로 내놔요.** 사용자가 복사해서 바로
  보낼 수 있어야 해요. 기안문처럼 구조가 있는 문서만 마크다운 블록으로 줘요.
- 본문 아래에 바꾼 이유를 두세 줄로만 붙여요. 문장별 해설은 하지 않아요.
- 채널이나 상대가 불분명하면 **가장 그럴듯한 쪽으로 하나를 쓰고**, 다른
  선택지가 있다는 걸 한 줄로 알려요. 초안 없이 되묻지 않아요.
- 길이 조정 요청("더 짧게", "더 정중하게")에는 새 버전만 다시 줘요.

## 하지 않는 것

- 원문에 없는 열의나 사과를 채워 넣지 않아요.
- 같은 인사말을 문단마다 반복하지 않아요.
- 사용자가 정중함을 요청했다고 문장을 길게 늘이지 않아요. 정중함은 길이가
  아니라 상대의 시간을 아끼는 데서 나와요.
- 상대를 압박하는 표현("아직 확인 못 받았습니다", "몇 번째 요청입니다")을
  쓰지 않아요. 기한과 영향만 사실대로 적어요.
